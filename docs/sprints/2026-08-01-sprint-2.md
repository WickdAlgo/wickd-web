# Sprint 2: 2026-08-01

## Sprint Goal

Turn `/platform` from a demonstration into the frontend host for the Wickd
platform: addressable routes, versioned contracts behind a gateway, a real
chart renderer, and causal replay proven end to end on one inspection run and
one trade.

## Product Alignment

- Executes phases W0–W5 of
  `Wickd_Web_Integrated_Trade_Journal_Handoff.md`, which decides the trade
  journal is a platform module rather than a standalone application or part of
  `Wickd.Core`.
- Opens `docs/releases/v0.2.0.md`.
- Amends `PRODUCT.md`, whose Boundaries section currently forbids what this
  sprint builds toward. That amendment is Item 1, not a side effect.
- Leaves `docs/releases/v0.1.0.md` closable: nothing here changes the marketing
  surface.

## Dates

- **Start:** 2026-08-01
- **End:** 2026-08-08
- **Cadence:** 1 week

## Capacity And Assumptions

- Single maintainer with agent assistance.
- **This sprint shares Sprint 1's window.** Sprint 1 was documentation-only and
  closed on its opening day with its Review and Retro filled, so Sprint 2 opens
  immediately rather than leaving the week idle. The overlap is deliberate, not
  a bookkeeping error.
- **Seven items in one week is an overcommitment**, and it was committed to
  knowingly. Items 1–4 are independently deployable and land first. If the
  window closes early, the carryover order is Item 5, then 6, then 7 — recorded
  here in advance so the decision is not made under pressure at review time.
- Two runtime dependencies enter a repository that has had three since it was
  created: `lightweight-charts` and `zod`. Bundle impact is a tracked risk, not
  an assumption.
- No backend exists and none is built. Every contract is provisional and every
  payload is a fixture. `Wickd.Inspection` will later be canonical, so the
  contracts sit behind one adapter boundary.
- Merging to `main` deploys. Everything here reaches production the moment the
  pull request lands, including the journal.

## Work Log

- 2026-08-01 — Sprint opened. Shares Sprint 1's window because Sprint 1 was
  documentation-only and closed on its opening day; leaving the week idle would
  have been the only alternative.
- 2026-08-01 — Scope decided as handoff phases W0–W5. W6 (remaining journal
  pages) and W7 (HTTP integration) excluded: W7 cannot start before
  `wickd-dotnet` exposes an API, and building W6's pages first would commit UI
  to contracts no backend has validated.
- 2026-08-01 — Four design decisions taken before implementation, each against
  a named alternative:
  - Contracts and chart code stay under `src/` rather than becoming
    `packages/*`. The handoff asks for workspace packages, but a Worker
    deployment with three runtime dependencies and no workspace tooling would
    pay build complexity for a boundary that has not yet proven stable.
    Extraction stays available; a disruptive move first does not.
  - Zod over hand-written type guards, so the schema is the single source of
    truth and inferred types cannot drift from their validators.
  - Chart overlays render as SVG driven by a pure projection seam, rather than
    canvas series primitives. Three reasons: SVG takes `var()` directly so
    token colors survive without runtime resolution, DOM elements give keyboard
    selection and focus for free, and geometry stays assertable in jsdom, which
    returns `null` from `getContext`.
  - `CandleChart` is kept, not replaced. It remains a server component serving
    the marketing routes, so no marketing bundle changes and there is no
    server-to-client boundary change outside `/platform`.
- 2026-08-01 — Item 1 complete. `PRODUCT.md` amended with a dated Amendments
  section rather than a silent edit, so the two clauses that were removed stay
  legible alongside the reason. The illustration constraint was strengthened
  rather than dropped — it now scales with how convincing the surface looks,
  which is the part Item 6 puts under real pressure.
- 2026-08-01 — Items 3 and 5 were built before Item 2, reversing the planned
  order. Writing the routes first would have meant wiring each view to fixture
  arrays and then rewiring it to the gateway a commit later; the contracts had
  to exist before the routes could consume them once.
- 2026-08-01 — Item 7's unit runner was pulled forward for the same reason. The
  contracts and the replay filters are the parts that can be wrong invisibly,
  and building them without a way to run them would have deferred every
  discovery below to browser inspection.
- 2026-08-01 — Item 2 complete. Two defects surfaced only in the browser, both
  in the fixture rather than the routes, and both worth recording because they
  are the same mistake:
  - The liquidity sweep printed an **inverted price band** (`67,555 – 67,145`).
    The structures were pinned to the clock times the old mock used, while the
    candles come from a pseudo-random walk — so the "sweep" candle never
    reached the pool it claimed to sweep. Structures are now *found in* the
    data by real, if crude, detectors: the pool is an actual prior high, the
    sweep is the actual first candle to exceed it, the gap is an actual
    three-candle gap. Nine tests now assert each relationship, so a generator
    change that breaks the story fails the suite.
  - Deriving the structures then reordered them, which left the relation graph
    claiming `eqh caused_by swing-high` when the swing high came *later*, and
    left the trade's entry zone in a different part of the session from the
    order block its thesis described. Relations are now asserted to point
    backwards in time, and the trade anchors to `may6SessionMarks` rather than
    to its own clock times.
- 2026-08-01 — Constrained structure detection to the first 75% of the session.
  Searching the full range put the swing high on the last candle, which made
  every consequence — mitigation, sweep rejection — unobservable.
- 2026-08-01 — The structure list now shows `MM-DD HH:MM`. A session spans 31
  hours, so the bare clock time it used to show made a correctly sorted list
  look unsorted.
- 2026-08-01 — Gave the platform a mobile layout. The previous shell had none:
  a fixed 200px rail on a 375px screen left the content 175px wide. The rail
  becomes a horizontally scrolling strip below `sm`.
- 2026-08-01 — Item 4 complete. Four bugs were only findable in a browser, and
  each one rendered *something* — which is why unit tests alone would not have
  caught them:
  - The projection measured the container instead of `chart.paneSize()`. The
    container also holds the price scale and the time axis, so every structure
    was stretched about 11% wide and 9% tall — drawn beside the candles it
    described rather than on them.
  - The overlays were painted over by the chart. Lightweight Charts gives its
    canvases `z-index: 1`; the SVG layers were at `auto`. The shapes were in the
    DOM with correct geometry and simply invisible, which reads exactly like a
    projection failure. `elementFromPoint` returning `CANVAS` was what
    identified it.
  - Zones were painted at the structure alpha (0.95) and hid the price action
    they describe. Zones now have their own alpha tokens. The original plan put
    them *under* the canvas instead, which would have solved the opacity but
    made them unclickable, since the chart's container sits between the shapes
    and the pointer.
  - `projectConnection` clamped x but not y, so a swing leg running off the
    left edge rendered at an angle it never had. Both axes are now raw for
    diagonals and the SVG viewport does the clipping, which clips along the
    true line.
- 2026-08-01 — Added a focus range. Opening on the full dataset is correct and
  useless: 372 five-minute candles across ~750px makes a single-candle order
  block about two pixels wide and one tall. The view opens on the middle 60% of
  the structure distribution instead — the extremes would drag it back to the
  full session, since a swing leg spans the session low to the session high by
  definition.
- 2026-08-01 — `attributionLogo` is disabled, which Apache-2.0 permits. The
  attribution moved to `README.md` under Third-party notices so the obligation
  is still met without putting the mark on the product's core artifact.
- 2026-08-01 — Resolved theme tokens are no longer held in React state. Reading
  them in an effect and storing the result cost a render on every mount and
  theme change for a value the chart's own layout effect can read directly;
  ESLint's `set-state-in-effect` rule flagged it, and it was right.
- 2026-08-01 — Item 6 complete. The trade page found two more fixture defects
  and one real leak in the replay filters:
  - The order-block search walked backwards without bound, so during a
    sustained rally it found the last down candle *anywhere* earlier in the
    session. The resulting "block" sat 2,000 points below the gap it supposedly
    caused, which put the trade's stop **above** its entry on a long and pushed
    the third target 13,000 points beyond any price the session reached. The
    search is now bounded to eight candles.
  - The entry fill was taken from whatever printed three candles after the
    signal rather than from inside the block the plan names, which is what made
    the breakeven stop land above the entry. It is now the midpoint of the
    zone — which is what "filled in the block" means.
  - **Outcome leak.** `sliceTradeAsOf` gated the execution record on when it
    opened, so replaying the entry displayed "net R 2.41" — handing the
    reviewer the answer before they had judged the decision. Visibility now has
    two stages: an execution appears when it opens, carrying its size and risk;
    its result appears only when it closes. Reported R is redacted too, since
    it is an outcome as well.
- 2026-08-01 — Carried `9642918` (WEB-BL-006 favicon validation) onto this
  branch. It sat on `docs/establish-development-cycle` after pull request #9
  merged, so it was on no `main` commit. `origin/docs/establish-development-cycle`
  should be deleted once this lands, or the commit will be offered for merge
  twice.
