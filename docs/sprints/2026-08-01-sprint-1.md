# Sprint 1: 2026-08-01

## Sprint Goal

Give `wickd-web` an explicit, traceable development cycle: a document hierarchy
that says where each kind of truth lives, an execution layer, and a release
model that matches a continuously deployed site.

## Product Alignment

- Establishes `PRODUCT.md` (web-surface constitution) and `DESIGN.md` (UI/UX
  source of truth), which every later sprint is measured against.
- Opens `docs/releases/v0.1.0.md`, the first release contract.
- Aligns this repository with the workflow already running in wickd-dotnet so
  agents moving between them do not have to relearn the process.

## Dates

- **Start:** 2026-08-01
- **End:** 2026-08-08
- **Cadence:** 1 week

## Capacity And Assumptions

- Single maintainer with agent assistance.
- Documentation-only sprint apart from one comment fix in `src/lib/version.ts`,
  so the risk to the live site is limited to the build staying green.
- Release model decided up front: deployment records, no tags, no GitHub
  Releases, version from `package.json` on its own stream.
- The site's product-wide vision stays canonical in wickd-dotnet; this
  repository does not fork it.

- 2026-08-01 — Item 2: Backlog IDs use the `WEB-BL-` prefix rather than

- 2026-08-01 — Both items verified: `pnpm lint`, `pnpm build`, the
  design-system validator, and `git diff --check` all green; every documented
  link resolves.
- 2026-08-01 — Review round on the pull request found three documentation
  errors, all confirmed against the source and fixed:
  - The changelog claimed a completed design-token migration. 17 hex literals
    remain in `src/` plus the favicon; the entry was narrowed and `WEB-BL-006`
    opened. The `v0.1.0` criterion now reads as unmet rather than done.
  - `AGENTS.md` asserted Workers Builds was the only deploy path while
    `pnpm deploy` shipped in `package.json` and was documented as a way to
    deploy. Manual deploys are now explicitly governed as an incident escape
    hatch instead of the invariant being asserted and contradicted.
  - The release runbook sent operators to the nav bar and mobile drawer to
    verify a version bump. The markers actually render in the marketing footer
    (web + core) and the platform sidebar (web only). The runbook was
    corrected, and the stale docblock in `src/lib/version.ts` that the claim
    was copied from was fixed at the source.
- 2026-08-01 — `src/lib/version.ts` is the one exception to this sprint being
  documentation-only: a comment-only correction, no runtime change.
- 2026-08-01 — Second review round, four more documentation errors, all
  confirmed against the source and fixed:
  - The changelog said CI runs on "every push"; `ci.yml` triggers on pushes to
    `main` and on pull requests only.
  - One changelog sentence implied both version markers are synced from
    wickd-dotnet. Only the Core marker is; the web marker follows
    `package.json`. Split into two claims.
  - `DESIGN.md` said all `wa-` keyframes live in `globals.css`;
    `animated-logo.tsx` defines `wa-replay-grow` in its own `<style>` block.
    Documented the self-contained-component exception rather than moving the
    keyframe, since colocating it is what makes the mark portable.
  - `PRODUCT.md` said generated content runs "in the browser". `CandleChart`
    has no client boundary, so on the marketing routes `genCandles()` runs at
    prerender. Reworded around the fixed seed instead of the execution site —
    the boundary that matters is that nothing is fetched and nothing is real.
- 2026-08-01 — Third review round, one finding, confirmed and fixed:
  `WEB-BL-006` asked for no hex literals anywhere but validated with a
  `.tsx`-only grep, so the favicon could have passed the check while still
  carrying its palette. The command now includes `.ts` and `.svg` (22 hits
  today, five of them in `icon.svg`), and the acceptance criterion says
  explicitly that the favicon is either migrated or exempted in writing.
- 2026-08-01 — Pattern worth keeping: every error in both rounds was a claim
  about the code that was true-sounding but unverified. The documents that
  route ("see X") aged well; the ones that restate ("X does Y") did not.
